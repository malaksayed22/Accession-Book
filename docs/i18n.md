# Internationalisation (English and Canadian French)

## How it works

- `next-intl` with a URL prefix: `/en/...` and `/fr/...`. The first visit negotiates from `Accept-Language` (`fr-CA`
  becomes `fr`); the choice is remembered in the `NEXT_LOCALE` cookie. `proxy.ts` composes, in order: asset and API
  bypass, language prefix, authentication gate (login redirect keeps the language), security headers.
- Routes live under `src/app/[locale]`. Links and router hooks come from `@/i18n/navigation`, which add the prefix;
  `redirect()` from `next/navigation` still works because the proxy adds it.
- `<html lang>` is set per request; the language switch buttons carry `lang` so screen readers pronounce them correctly.
- Dates and numbers use the `fr-CA`/`en-CA` conventions through `useFormatter`/`getFormatter`, in the laboratory time
  zone (`LAB_TIMEZONE`) so server and browser agree. Regulatory exports keep ISO dates.

## Messages

`messages/<locale>/<area>.json`, one file per area (`common`, `ui`, `shell`, `auth`, `errors`, `profile`); the file name
is the namespace. Keys are typed from the English files (`src/i18n/global.d.ts`), so a typo is a compile error.
ICU syntax for variables and plurals: `{count, plural, one {# unit} other {# units}}`. French uses typographic
apostrophes (’) and non-breaking spaces before `:` `?` `!` where the sentence requires them.

**Guards (all run in CI):**
`src/i18n/messages.test.ts` fails on a key missing in either language, a placeholder that differs, an empty message, a
French sentence identical to English, or a straight apostrophe in French. ESLint `i18next/no-literal-string` fails on
JSX text literals in every translated area (list in `eslint.config.mjs`; it grows as sections are rebuilt).

## Errors

The API returns a stable `code` (`INVALID_CREDENTIALS`, `PASSWORD_POLICY`, `RATE_LIMITED`, ...) and, where the sentence
needs data, `params` (`issue`, `retryAfterSeconds`). The English `error` string is only a fallback for non-browser
clients. The UI turns the code into a sentence with `useApiError()` (`src/lib/api-error.ts`).

## Status and what is left

Translated now: shell, navigation, command palette, sign-in, two-step verification, invitation, profile and security,
error and not-found pages, the design-system components. The marketing site and the section pages (dashboard, units,
experiments, ...) still render English in both languages; they are translated as each is rebuilt in P5.

**French copy has not been reviewed by a translator.** Before go-live, have a Quebec-based professional review all
`messages/fr` files, in particular regulatory terms: "retenue qualité" (quality hold), "traçage de rappel" (recall
trace), "registre des destructions", and the Health Canada system name (CTLS is left as the English acronym until the
customer confirms the official French name).
